# 📦 Домашний склад — учёт вещей в коробках и ящиках

Веб-приложение: **REST API на FastAPI** + **интерфейс на React**. Данные
хранятся в **локальном файле Excel** на вашем сервере — никаких внешних
сервисов, аккаунтов, API-ключей и подписок. Таблица и есть база данных.

## Структура проекта

Приложение слоистое: `frontend → api → services → domain ← storage`.
Хранилище (файл Excel) знает только про файл; сервисный слой — про сценарии;
API касается только сервисов и никогда не трогает файл напрямую; React-фронтенд
общается с backend только через REST.

```
.
```

## Структура файла данных

Файл `inventory.xlsx` создаётся автоматически при первом запуске.

**Лист «Ящики»**

| ID | Название | Место_ID | Описание | Создан |
|----|----------|----------|----------|--------|

**Лист «Вещи»**

| ID | Название | Ящик_ID | Количество | Категория | Заметки | Обновлён |
|----|----------|---------|------------|-----------|---------|----------|

**Лист «Корзина»** (создаётся автоматически при первом удалении)

| Тип | ID | Название | Данные | Родитель_ID | Дата удаления |
|-----|----|----------|--------|-------------|---------------|

`Тип` — «вещь» / «ящик» / «место»; `Данные` — JSON исходной строки удалённой
записи (все значения её листа сохраняются целиком); `Родитель_ID` — `Ящик_ID`
у вещей, `Место_ID` у ящиков. Записи старше 30 дней скрываются и вычищаются
при открытии корзины. Лист можно удалить в Excel — он пересоздастся при
следующем удалении; три основных листа никогда не меняются, поэтому старые
файлы открываются как раньше.

`ID` — случайный 8-символьный идентификатор. Вещи ссылаются на ящик через `Ящик_ID`.

## Быстрый старт

### Шаг 0 — один раз: Python 3.13 и Node.js LTS

- Python 3.13 — с [python.org](https://www.python.org/downloads/) или
  `winget install Python.Python.3.13`.
- Node.js LTS (нужен для фронтенда) — с [nodejs.org](https://nodejs.org/) или
  `winget install OpenJS.NodeJS.LTS`.

### Шаг 1 — backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt -r requirements-dev.txt

# (необязательно) свой файл данных и настройки
copy .env.example .env

# запуск API: http://localhost:8000
.venv\Scripts\python -m uvicorn app.api.main:app --port 8000 --reload
```

Проверка: `http://localhost:8000/api/health` → `{"status":"ok"}`.
Интерактивные доки всех методов — `http://localhost:8000/docs`.

### Шаг 2 — frontend (в отдельном терминале)

```bash
cd frontend
npm install
npm run dev
```

Страница откроется на `http://localhost:5173` и покажет сводку склада
(ящики, вещи, единицы, места) из реального Excel.

### Одной командой

После разовой установки зависимостей (шаги 1–2 без запуска):

```bash
npm install        # в корне (ставит concurrently)
npm run dev        # поднимает API и фронтенд вместе
```

Скрипты раздельного запуска: `npm run dev:api`, `npm run dev:web`.

**Никаких ключей и аккаунтов настраивать не нужно** — файл данных создастся сам.

## REST API

Полный CRUD по всем сущностям: места хранения, ящики, вещи, корзина, поиск,
резервная копия. Схемы запросов и ответов — английские snake_case (`id`,
`name`, `box_id`, `quantity`, `updated_at`…); формат файла данных не меняется.
Все эндпоинты и модели — интерактивно в `/docs`.

| Метод | Путь | Назначение |
|--------|------|------------|
| GET | `/api/health` | Проверка живости API |
| GET | `/api/stats` | Сводка: ящики, вещи, единицы, места |
| GET | `/api/locations` | Места хранения (+`box_count`) |
| POST | `/api/locations` | Создать место (дубликат имени → 409) |
| DELETE | `/api/locations/{id}` | Убрать место в корзину (ящики остаются) |
| GET | `/api/boxes` | Ящики (+`location_name`, `item_count`, `unit_count`) |
| POST | `/api/boxes` | Создать ящик (несуществующее место → 404) |
| GET | `/api/boxes/{id}` | Ящик с вещами внутри |
| DELETE | `/api/boxes/{id}` | Убрать ящик в корзину (вещи остаются) |
| GET | `/api/boxes/{id}/qr` | PNG QR-код со ссылкой на страницу ящика |
| GET | `/api/items` | Вещи; фильтры `?box_id=`, `?category=` |
| POST | `/api/items` | Добавить вещь (`quantity` ≥ 1) |
| PATCH | `/api/items/{id}` | Частичное обновление; `box_id` — перенос, пустой — «без ящика» |
| POST | `/api/items/{id}/move` | Перенести вещь в другой ящик |
| DELETE | `/api/items/{id}` | Убрать вещь в корзину |
| DELETE | `/api/items?ids=a,b` | Массово убрать в корзину (дубликаты пропускаются) |
| PUT | `/api/items` | Bulk-save таблицы вещей → `{saved: N}` |
| GET | `/api/search?q=` | Поиск по названию, категории, заметкам, подписи ящика |
| GET | `/api/categories` | Справочник категорий (из вещей, по алфавиту) |
| GET | `/api/trash` | Корзина (просроченные вычищаются) → `{entries, purged}` |
| POST | `/api/trash/{kind}/{id}/restore` | Восстановить; `kind` ∈ `item`/`box`/`location` |
| DELETE | `/api/trash` | Очистить корзину → `{deleted: N}` |
| POST | `/api/backup` | Резервная копия файла → `{path}` |
| POST | `/api/cache/clear` | Сбросить кэш чтений (204) |

Ошибки отдаются как `{"detail": "текст"}`: `400` — нарушение инвариантов
(пустое название, отрицательное количество), `404` — запись или ящик не
найдены, `409` — дубликат имени места хранения, `503` — сбой хранилища
(файл повреждён), `422` — тело запроса не прошло pydantic-валидацию. Тексты
ошибок — пользовательский контракт, совпадают с прежним приложением.

## Порты и CORS

| Сервис | Адрес | Зачем |
|--------|-------|-------|
| Backend API | `http://localhost:8000` | REST API (таблица выше) и доки (`/docs`) |
| Frontend dev-сервер | `http://localhost:5173` | Страница React, порт фиксирован (strictPort) |

Запросы с фронтенда к API — кросс-доменные (5173 → 8000), поэтому backend
открывает их через `CORSMiddleware`. Список разрешённых источников — в
переменной `CORS_ORIGINS`; по умолчанию разрешён только
`http://localhost:5173`.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|------------|-------------|--------------|----------|
| `DATA_FILE` | нет | `/data/inventory.xlsx` | Путь к файлу-хранилищу (backend) |
| `APP_TITLE` | нет | `📦 Домашний склад` | Заголовок приложения |
| `BASE_URL` | нет | — | Базовый URL для QR-кодов ящиков; без него — адрес запроса |
| `CORS_ORIGINS` | нет | `http://localhost:5173` | Разрешённые источники фронтенда, через запятую |
| `VITE_API_URL` | нет | `http://localhost:8000` | Адрес API для фронтенда (frontend/.env) |

Шаблоны: `backend/.env.example`, `frontend/.env.example`.

## Важно: как правильно редактировать файл

Приложение читает файл в память и **перезаписывает его целиком** при каждом
изменении. Поэтому:

- ⚠️ **Не редактируйте файл в Excel одновременно с работающим приложением.**
  Если открыть файл в Excel, что-то поменять и сохранить, а затем внести
  изменение через приложение — правки из Excel будут **потеряны**.
- ✅ Если нужно поправить файл руками — остановите backend, отредактируйте
  файл и запустите снова.

Файл открывается в Excel, LibreOffice и Google Таблицах — можно посмотреть
глазами, распечатать или отдать кому-то. Резервная копия — `POST /api/backup`
(копия с отметкой времени рядом с файлом).

## Разработка и тесты

Проект покрыт тестами (pytest) на уровне домена, миграции legacy-формата,
хранилища, сервисного слоя и API. Фикстуры файлов данных создаются
программно через openpyxl; реальные данные в репозиторий не попадают.

```bash
# тесты backend — запускать из каталога backend/
cd backend
.venv\Scripts\python -m pytest

# с отчётом покрытия
.venv\Scripts\python -m pytest --cov=app --cov-report=term-missing

# проверка типов и сборка фронтенда
cd frontend
npm run build
```

Структура тестов:

```
backend/tests/
├── conftest.py                # генераторы xlsx-фикстур (новый и legacy-формат)
├── test_domain.py             # инварианты моделей, генерация ID
├── test_forms.py              # нормализация и выбор категории (домен)
├── test_helpers.py            # чистые хелперы данных
├── test_migration.py          # миграция legacy-файлов (слияние мест и т.д.)
├── test_excel_repository.py   # round-trip, атомарность, ошибки, сбои I/O
├── test_service.py            # сценарии: перенос, удаление, поиск, кэш
├── test_trash.py              # корзина: expiry, восстановление, detach/reattach
├── test_config_context.py     # конфигурация и сборка сервиса
├── test_api.py                # REST API: health, stats, ошибка хранилища → 503
├── test_api_locations.py      # API мест: список со счётчиками, 409 дубликат, корзина
├── test_api_boxes.py          # API ящиков: счётчики, деталь, 404, detach вещей
├── test_api_items.py          # API вещей: CRUD, PATCH, bulk, поиск, категории
├── test_api_trash.py          # API корзины: restore, purge, бэкап, кэш
└── test_api_qr.py             # QR-коды ящиков: PNG, 404
```

При доработках держите направление зависимостей:
`api → services → domain ← storage`. Домен не импортирует ничего из остальных
слоёв; openpyxl импортируется только в `app/storage/`; `fastapi` — только в
`app/api/`. Сервисы зависят от абстракции `InventoryRepository`
(typing.Protocol) — подменить хранилище можно в одном месте, `app/context.py`.

## Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| Страница 5173 показывает error-state | Backend не запущен. Проверьте `http://localhost:8000/api/health` или запустите `npm run dev:api`. |
| Запрос к API падает с CORS-ошибкой в консоли | Адрес фронтенда не в `CORS_ORIGINS` backend. Добавьте источник (по умолчанию нужен `http://localhost:5173`). |
| `Файл повреждён или не является книгой Excel` | Файл испорчен. Восстановите из копии или удалите — приложение создаст новый. |
| Изменения не видны сразу | Данные кэшируются на 30 секунд; перезапуск backend сбрасывает кэш. |
| Порт 5173 занят | strictPort не даёт Vite переехать. Освободите порт или поменяйте его в `frontend/vite.config.ts` (и в `CORS_ORIGINS`). |

## Почему не Google Таблицы

Изначально проект использовал Google Sheets. От этого отказались:

- не нужен сервисный аккаунт, JSON-ключ и расшаривание таблицы;
- не нужны включённые Google Sheets/Drive API и квоты;
- нет зависимости от доступности внешнего сервиса;
- нет ограничения в 10 млн ячеек и лимитов на запросы;
- файл лежит у вас и открывается в Excel.

У Яндекс Таблиц, к слову, публичного API для работы с ячейками нет вообще —
только файловый API Яндекс Диска, что для учёта неудобно и рискованно.
