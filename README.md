# 📦 Домашний склад — учёт вещей в коробках и ящиках

Веб-приложение на Streamlit. Данные хранятся в **локальном файле Excel** на вашем
сервере — никаких внешних сервисов, аккаунтов, API-ключей и подписок.
Таблица и есть база данных.

## Структура проекта

Приложение слоистое: `ui → services → domain ← storage`. Хранилище
(файл Excel) знает только про файл; сервисный слой — про сценарии; интерфейс
касается только сервисов и никогда не трогает файл напрямую.

```
.
├── main.py                    # Точка входа: streamlit run main.py
├── app/
│   ├── config.py              # Конфигурация из переменных окружения (DATA_FILE, APP_TITLE, BASE_URL)
│   ├── context.py             # Точка сборки: репозиторий + кэш + сервис
│   ├── domain/                # Домен: сущности и инварианты (ни от чего не зависит)
│   │   ├── models.py          #   Location, Box, Item + валидация
│   │   ├── ids.py             #   генерация 8-символьных ID
│   │   ├── errors.py          #   StorageError, ValidationError
│   │   ├── fields.py          #   канонические названия колонок листов
│   │   └── trash.py           #   корзина: типы записей, срок 30 дней, expiry
│   ├── storage/               # Хранилище (единственное место с openpyxl)
│   │   ├── excel_repository.py#   ExcelRepository: чтение/запись/атомарное сохранение/RLock
│   │   ├── migration.py       #   миграция legacy-файлов (текст «Место» → лист «Места»)
│   │   └── schema.py          #   схема листов, чтение в DataFrame
│   ├── services/              # Сценарии использования
│   │   ├── repository.py      #   InventoryRepository (typing.Protocol)
│   │   ├── inventory_service.py # InventoryService: создание/перенос/удаление/поиск/бэкап
│   │   └── caching.py         #   кэш чтений на 30 секунд (st.cache_data)
│   └── ui/                    # Интерфейс Streamlit (только этот слой знает про st)
│       ├── navigation.py      #   сборка страниц, боковая панель
│       ├── styles.py          #   темы, CSS
│       ├── helpers.py         #   подписи, карточки, пустые состояния
│       ├── item_cards.py      #   карточки вещей со степперами (фрагменты)
│       ├── trash.py           #   полоса отмены удаления (undo), иконки корзины
│       ├── forms.py           #   формы создания ящиков и вещей
│       ├── qr.py              #   QR-коды ящиков
│       └── pages/             #   по модулю на раздел: обзор, поиск, ящик,
│                              #   вещи, добавить, редактировать, места, корзина
├── tests/                     # pytest: домен, миграция, хранилище, сервисы
├── requirements.txt           # Зависимости приложения (Streamlit ≥ 1.66)
├── requirements-dev.txt       # Зависимости для разработки (pytest, pytest-cov)
├── .streamlit/
│   └── config.toml            # Тема оформления (тёмная по умолчанию)
├── Dockerfile                 # Образ на python:3.10-slim
├── docker-compose.yml         # Запуск, порты, том для данных
├── .env.example               # Шаблон переменных окружения
├── .dockerignore
└── .gitignore
```

## Структура файла данных

Файл `inventory.xlsx` создаётся автоматически при первом запуске.

**Лист «Ящики»**

| ID | Название | Место_ID | Описание | Создан |
|----|----------|----------|----------|--------|

**Лист «Вещи»**

| ID | Название | Ящик_ID | Количество | Категория | Заметки | Обновлён |
|----|----------|---------|------------|-----------|---------|----------|

**Лист «Корзина»** (создаётся автоматически при первом удалении)

| Тип | ID | Название | Данные | Родитель_ID | Дата удаления |
|-----|----|----------|--------|-------------|---------------|

`Тип` — «вещь» / «ящик» / «место»; `Данные` — JSON исходной строки удалённой
записи (все значения её листа сохраняются целиком); `Родитель_ID` — `Ящик_ID`
у вещей, `Место_ID` у ящиков. Записи старше 30 дней скрываются и вычищаются
при открытии корзины. Лист можно удалить в Excel — он пересоздастся при
следующем удалении; три основных листа никогда не меняются, поэтому старые
файлы открываются как раньше.

`ID` — случайный 8-символьный идентификатор. Вещи ссылаются на ящик через `Ящик_ID`.

## Быстрый старт

```bash
# Каталог проекта
mkdir -p ~/home-inventory && cd ~/home-inventory

# Скопируйте сюда: main.py, каталог app/, requirements.txt, Dockerfile,
# docker-compose.yml, .env.example, .streamlit/

# (необязательно) создайте .env из шаблона
cp .env.example .env

# Собрать и запустить в фоне
docker compose up -d --build

# Проверить статус (должно быть healthy)
docker compose ps

# Смотреть логи
docker compose logs -f

# Остановить
docker compose down
```

Приложение будет доступно по адресу `http://<IP-сервера>:8501`.

**Никаких ключей и аккаунтов настраивать не нужно** — файл данных создастся сам.

### Вариант без docker compose

```bash
docker build -t home-inventory:latest .

docker volume create inventory-data

docker run -d \
  --name home-inventory \
  --restart unless-stopped \
  -p 8501:8501 \
  -e DATA_FILE=/data/inventory.xlsx \
  -v inventory-data:/data \
  home-inventory:latest
```

## Где лежат данные

Данные — в именованном томе `inventory-data`, внутри контейнера это
`/data/inventory.xlsx`. Том переживает пересборку образа и удаление контейнера.

```bash
# Скачать файл на хост (посмотреть в Excel)
docker compose cp home-inventory:/data/inventory.xlsx ./

# Загрузить файл обратно (например, восстановление из копии)
docker compose cp ./inventory.xlsx home-inventory:/data/inventory.xlsx

# Посмотреть, где том лежит на хосте
docker volume inspect home-storage_inventory-data
```

Резервную копию можно сделать и из интерфейса — кнопка **«💾 Резервная копия»**
в боковой панели создаёт рядом копию с отметкой времени.

## Возможности UI

Интерфейс оформлен как современный дашборд: тёмная тема по умолчанию
(инд #0F1117, карточки с мягкими рамками, акцентный цвет — индиго),
светлая тема по кнопке в боковой панели. Шрифт — системный Inter/system-ui,
все числа выводятся с табличными цифрами. Внешних запросов нет: стили
и шрифты встроены, зависимости ставятся из pip при сборке.

- **🗂 Навигация** — боковая панель с иконками (сворачивается на мобильных):
  Обзор, Поиск, Ящик, Вещи, Добавить, Редактировать, Места, Корзина. Активный
  раздел подсвечивается.
- **📊 Обзор (главная)** — карточки статистики (ящики, позиции, единицы,
  места), быстрый поиск, список ящиков с живыми счётчиками и кнопкой
  «Открыть», блок «Недавно обновлённое». Старая глубокая ссылка
  `/?box=<ID>` с существующим ящиком открывает страницу «Ящик»; с
  несуществующим — обычный Обзор с предупреждением. Пустой склад встречает
  подсказкой и кнопкой «Добавить первый ящик».
- **🔍 Поиск** — глобальный поиск по названию, категории, заметкам и названию
  ящика; результаты — карточки с чипами категорий, степпером количества
  «−/+» и удалением в корзину через поповер.
- **📦 Ящик** — карточка ящика с бейджем места, QR-код (ссылка
  `BASE_URL/box?box=<ID>`, старые QR-коды `/?box=<ID>` тоже работают),
  содержимое карточками; клики «−/+» обновляют только карточку, без полной
  перезагрузки страницы.
- **📋 Вещи** — редактор таблицы: фильтр «на лету», правка ячеек, добавление
  строк, удаление по галочке и «💾 Сохранить» (отмеченные строки убираются
  в корзину). При активном фильтре строки, скрытые фильтром, сохраняются
  без изменений (не теряются).
- **➕ Добавить** — переключатель «Новый ящик / Новая вещь», формы с
  подсказками и тостами вместо перезагрузки страницы. Категория вещи
  выбирается из общего списка (используемые всеми вещи категории) или
  заводится новая.
- **✏️ Редактировать** — крупный степпер количества, точный ввод, перенос
  между ящиками, правка полей, удаление ящика (ящик переезжает в корзину,
  вещи остаются и отображаются как «— без ящика —»).
- **🗺 Места** — список мест хранения карточками со счётчиком привязанных
  ящиков; удаление места переносит его в корзину, ящики остаются и
  отображаются как «— без места хранения —».
- **🗑 Корзина** — безопасное удаление вместо необратимого: любое удаление
  (вещь, ящик, место) переносит запись в корзину на 30 дней. Сразу после
  удаления вверху страницы появляется полоса «Только что удалено: …
  [Отменить]» (плюс тост-уведомление); полоса исчезает при переходе на
  другую страницу, через 30 секунд или при новом удалении. На странице
  «Корзина» — список удалённых записей с указанием типа, происхождения
  («из ящика «X»») и даты, кнопка «Восстановить» у каждой записи и
  «Очистить корзину» с подтверждением. Восстановление возвращает записи
  с прежними ID: вещь возвращается в свой ящик (если он тоже был удалён —
  вернётся в него при восстановлении ящика), ящик — на своё место.
  Записи старше 30 дней скрываются и вычищаются при открытии корзины.
- **🌓 Темы** — тёмная по умолчанию; кнопка «☀️ Светлая тема» в панели
  переключает палитру (выбор запоминается в ссылке `?theme=light`), а выбор
  Light/Dark в меню Settings Streamlit (⚙️ в шапке) меняет тему целиком,
  включая таблицу-редактор.
- **🔔 Уведомления** — все действия (создание, перенос, удаление, копия)
  подтверждаются тостами; данные кэшируются на 30 секунд, кнопка
  «🔄 Обновить данные» сбрасывает кэш, «💾 Резервная копия» создаёт копию
  файла с отметкой времени.

Интерфейс адаптивный: карточки и степперы остаются в одну строку на
мобильных, боковая панель сворачивается в «бургер», горизонтального скролла
нет.

## Важно: как правильно редактировать файл

Приложение читает файл в память и **перезаписывает его целиком** при каждом
изменении. Поэтому:

- ✅ **Правьте данные через приложение** — в браузере, вкладка «📋 Таблица».
- ⚠️ **Не редактируйте файл в Excel одновременно с работой приложения.**
  Если открыть файл в Excel, что-то поменять и сохранить, а затем внести
  изменение через приложение — правки из Excel будут **потеряны**.

Если всё же нужно поправить файл руками:

```bash
# 1. Остановить приложение
docker compose stop

# 2. Скачать файл, отредактировать, загрузить обратно
docker compose cp home-inventory:/data/inventory.xlsx ./
# ... правите inventory.xlsx в Excel ...
docker compose cp ./inventory.xlsx home-inventory:/data/inventory.xlsx

# 3. Запустить снова
docker compose start
```

Файл открывается в Excel, LibreOffice и Google Таблицах — можно посмотреть
глазами, распечатать или отдать кому-то.

## Разработка и тесты

Проект покрыт тестами (pytest) на уровне домена, миграции legacy-формата,
хранилища и сервисного слоя — интерфейс тестируется вручную. Фикстуры файлов
данных создаются программно через openpyxl; реальные данные в репозиторий
не попадают.

```bash
# локально, в виртуальном окружении
python -m venv .venv
.venv\Scripts\activate            # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt -r requirements-dev.txt

# запустить тесты
pytest

# с отчётом покрытия
pytest --cov=app --cov-report=term-missing

# запустить приложение без Docker
streamlit run main.py
# либо короче — скрипт сам перезапустит себя через streamlit
python main.py
```

Структура тестов:

```
tests/
├── conftest.py                # генераторы xlsx-фикстур (новый и legacy-формат)
├── test_domain.py             # инварианты моделей, генерация ID
├── test_migration.py          # миграция legacy-файлов (слияние мест и т.д.)
├── test_excel_repository.py   # round-trip, атомарность, ошибки, сбои I/O
├── test_service.py            # сценарии: перенос, удаление, поиск, кэш
└── test_config_context.py     # конфигурация и сборка сервиса
```

При доработках держите направление зависимостей: `ui → services → domain ← storage`.
Домен не импортирует ничего из остальных слоёв; openpyxl импортируется только
в `app/storage/`; `streamlit` — только в `app/ui/` (плюс кэш-обёртка в
`app/services/caching.py`). Сервисы зависят от абстракции
`InventoryRepository` (typing.Protocol) — подменить хранилище можно в одном
месте, `app/context.py`.

## Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `permission denied` при записи файла | Том принадлежит другому пользователю. Контейнер работает от UID 1000; проверьте права на том. |
| `Файл повреждён или не является книгой Excel` | Файл испорчен. Восстановите из копии или удалите — приложение создаст новый. |
| Порт занят | Измените проброс в `docker-compose.yml`, например `"8502:8501"`. |
| Изменения не видны сразу | Данные кэшируются на 30 секунд. Нажмите «🔄 Обновить данные» в боковой панели. |
| Правки из Excel пропали | Файл редактировался при работающем приложении. См. раздел выше. |

---

## Безопасность

- Контейнер работает от непривилегированного пользователя `appuser` (UID 1000).
- Данные не покидают ваш сервер — нет ни одного внешнего запроса.
- **У приложения нет собственной аутентификации.** Если сервер смотрит в
  интернет, закройте порт 8501 файрволом или поставьте перед ним reverse-proxy
  с Basic Auth (nginx / Caddy / Traefik).

## Почему не Google Таблицы

Изначально проект использовал Google Sheets. От этого отказались:

- не нужен сервисный аккаунт, JSON-ключ и расшаривание таблицы;
- не нужны включённые Google Sheets/Drive API и квоты;
- нет зависимости от доступности внешнего сервиса;
- нет ограничения в 10 млн ячеек и лимитов на запросы;
- файл лежит у вас и открывается в Excel.

У Яндекс Таблиц, к слову, публичного API для работы с ячейками нет вообще —
только файловый API Яндекс Диска, что для учёта неудобно и рискованно.
