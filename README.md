# 📦 Домашний склад — учёт вещей в коробках и ящиках

Веб-приложение: **REST API на FastAPI** + **интерфейс на React** с входом
по логину и паролю и ролями «администратор»/«просмотр». Данные (включая
учётные записи) хранятся в **локальном файле Excel** на вашем сервере —
никаких внешних сервисов, API-ключей и подписок. Таблица и есть база данных.

## Структура проекта

Приложение слоистое: `frontend → api → services → domain ← storage`.
Хранилище (файл Excel) знает только про файл; сервисный слой — про сценарии;
API касается только сервисов и никогда не трогает файл напрямую; React-фронтенд
общается с backend только через REST.

## Структура файла данных

Файл `inventory.xlsx` создаётся автоматически при первом запуске.

**Лист «Ящики»**

| ID | Название | Место_ID | Описание | Создан |
|----|----------|----------|----------|--------|

**Лист «Вещи»**

| ID | Название | Ящик_ID | Количество | Категория | Заметки | Обновлён |
|----|----------|---------|------------|-----------|---------|----------|

**Лист «Корзина»** (создаётся автоматически при первом удалении)

| Тип | ID | Название | Данные | Родитель_ID | Дата удаления |
|-----|----|----------|--------|-------------|---------------|

`Тип` — «вещь» / «ящик» / «место»; `Данные` — JSON исходной строки удалённой
записи (все значения её листа сохраняются целиком); `Родитель_ID` — `Ящик_ID`
у вещей, `Место_ID` у ящиков. Записи старше 30 дней скрываются и вычищаются
при открытии корзины. Лист можно удалить в Excel — он пересоздастся при
следующем удалении; три основных листа никогда не меняются, поэтому старые
файлы открываются как раньше.

**Лист «Категории»** (создаётся автоматически при первой категории,
добавленной на странице настроек — кнопка ⚙ в правом верхнем углу)

| Название |
|----------|

Это справочник «впрок»: категории можно завести заранее, без единой вещи.
Общий список категорий в формах и фильтрах — объединение этого листа и
категорий, уже используемых у вещей (без учёта регистра, по алфавиту).
Переименование категории обновляет её у всех вещей; удаление делает вещи
«без категории». Лист можно удалить в Excel — он пересоздастся при
следующей добавленной категории.

**Лист «Пользователи»** (создаётся автоматически при первой регистрации)

| ID | Логин | Хеш_Пароля | Роль | Создан | Заблокирован |
|----|-------|------------|------|--------|--------------|

`Роль` — «администратор» (полный доступ) или «просмотр» (только чтение);
`Хеш_Пароля` — PBKDF2-HMAC-SHA256 со случайной солью
(`pbkdf2_sha256$итерации$соль$хеш`), пароли в открытом виде не хранятся;
`Заблокирован` — отметка времени блокировки или пустая строка.

**Лист «Сессии»** (создаётся автоматически при первом входе)

| Токен | ID_Пользователя | Создан |
|-------|-----------------|--------|

`Токен` — значение HttpOnly-cookie `storage_session`; сессия живёт до
выхода пользователя (logout) или удаления учётной записи. Оба листа можно
удалить в Excel — они пересоздадутся (пользователям придётся войти заново).

`ID` — случайный 8-символьный идентификатор. Вещи ссылаются на ящик через `Ящик_ID`.

## Быстрый старт

### Шаг 0 — один раз: Python 3.13 и Node.js LTS

- Python 3.13 — с [python.org](https://www.python.org/downloads/) или
  `winget install Python.Python.3.13`.
- Node.js LTS (нужен для фронтенда) — с [nodejs.org](https://nodejs.org/) или
  `winget install OpenJS.NodeJS.LTS`.

### Шаг 1 — backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt -r requirements-dev.txt

# (необязательно) свой файл данных и настройки
copy .env.example .env

# запуск API: http://localhost:8000
.venv\Scripts\python -m uvicorn app.api.main:app --port 8000 --reload
```

Проверка: `http://localhost:8000/api/health` → `{"status":"ok"}`.
Интерактивные доки всех методов — `http://localhost:8000/docs`.

### Шаг 2 — frontend (в отдельном терминале)

```bash
cd frontend
npm install
npm run dev
```

Страница откроется на `http://localhost:5173` — сначала форма входа:
зарегистрируйте первую учётную запись (она автоматически получит роль
«администратор»), затем создайте остальные учётные записи на странице
«Пользователи» — полный интерфейс склада: обзор, ящики с QR-кодами, вещи
с bulk-таблицей, места, корзина и поиск.

### Одной командой

После разовой установки зависимостей (шаги 1–2 без запуска):

```bash
npm install        # в корне (ставит concurrently)
npm run dev        # поднимает API и фронтенд вместе
```

Скрипты раздельного запуска: `npm run dev:api`, `npm run dev:web`.

**Никаких ключей и аккаунтов настраивать не нужно** — файл данных создастся сам.

## REST API

Доступ разграничен на серверной стороне: чтение данных склада — любой
авторизованной учётной записи (401 без сессии), все мутации и управление
пользователями — только «администратору» (403 остальным). Исключение —
`GET /api/health` и `/api/auth/*` (вход/регистрация). Схемы запросов и
ответов — английские snake_case (`id`, `name`, `box_id`, `quantity`,
`updated_at`…); формат файла данных не меняется. Все эндпоинты и модели —
интерактивно в `/docs`.

| Метод | Путь | Доступ | Назначение |
|--------|------|--------|------------|
| GET | `/api/health` | публично | Проверка живости API |
| GET | `/api/stats` | вход | Сводка: ящики, вещи, единицы, места |
| POST | `/api/auth/register` | публично | Регистрация (роль «просмотр»; первая учётная запись — «администратор») + вход |
| POST | `/api/auth/login` | публично | Вход по логину и паролю (401 — неверные данные или блокировка) |
| POST | `/api/auth/logout` | публично | Выход: сессия удаляется, cookie сбрасывается (204) |
| GET | `/api/auth/me` | вход | Текущий пользователь сессии |
| GET | `/api/users` | админ | Учётные записи (без хешей) |
| POST | `/api/users` | админ | Создать учётную запись с любой ролью (дубликат логина → 409) |
| PATCH | `/api/users/{id}` | админ | Логин, пароль (пустой — не менять), роль, блокировка |
| DELETE | `/api/users/{id}` | админ | Удалить учётную запись вместе с сессиями (204) |
| GET | `/api/locations` | вход | Места хранения (+`box_count`) |
| POST | `/api/locations` | админ | Создать место (дубликат имени → 409) |
| PATCH | `/api/locations/{id}` | админ | Частичное обновление: название (дубликат → 409), описание |
| DELETE | `/api/locations/{id}` | админ | Убрать место в корзину (ящики остаются) |
| GET | `/api/boxes` | вход | Ящики (+`location_name`, `item_count`, `unit_count`) |
| POST | `/api/boxes` | админ | Создать ящик (несуществующее место → 404) |
| PATCH | `/api/boxes/{id}` | админ | Частичное обновление: название, место (пустое — «без места»), описание |
| GET | `/api/boxes/{id}` | вход | Ящик с вещами внутри |
| DELETE | `/api/boxes/{id}` | админ | Убрать ящик в корзину (вещи остаются) |
| GET | `/api/boxes/{id}/qr` | вход | PNG QR-код со ссылкой на страницу ящика |
| GET | `/api/items` | вход | Вещи; фильтры `?box_id=`, `?category=` |
| POST | `/api/items` | админ | Добавить вещь (`quantity` ≥ 1) |
| PATCH | `/api/items/{id}` | админ | Частичное обновление; `box_id` — перенос, пустой — «без ящика» |
| POST | `/api/items/{id}/move` | админ | Перенести вещь в другой ящик |
| DELETE | `/api/items/{id}` | админ | Убрать вещь в корзину |
| DELETE | `/api/items?ids=a,b` | админ | Массово убрать в корзину (дубликаты пропускаются) |
| PUT | `/api/items` | админ | Bulk-save таблицы вещей → `{saved: N}` |
| GET | `/api/search?q=` | вход | Поиск по названию, категории, заметкам, подписи ящика |
| GET | `/api/categories` | вход | Справочник категорий: сохранённые + используемые у вещей, по алфавиту |
| POST | `/api/categories` | админ | Добавить категорию в справочник (дубликат без учёта регистра → 409) |
| PATCH | `/api/categories` | админ | Переименовать категорию у всех вещей → `{name, items_updated}` |
| DELETE | `/api/categories?name=` | админ | Удалить категорию; вещи станут «без категории» → `{name, items_updated}` |
| GET | `/api/trash` | вход | Корзина (просроченные вычищаются) → `{entries, purged}` |
| POST | `/api/trash/{kind}/{id}/restore` | админ | Восстановить; `kind` ∈ `item`/`box`/`location` |
| DELETE | `/api/trash` | админ | Очистить корзину → `{deleted: N}` |
| POST | `/api/backup` | админ | Резервная копия файла → `{path}` |
| POST | `/api/cache/clear` | админ | Сбросить кэш чтений (204) |

Ошибки отдаются как `{"detail": "текст"}`: `400` — нарушение инвариантов
(пустое название, отрицательное количество, пустое имя категории, плохой
логин/пароль, попытка понизить последнего администратора), `401` — нет
действительной сессии (`Требуется вход в систему.`), неверный логин или
пароль, заблокированная учётная запись, `403` — операция требует роли
«администратор», `404` — запись, ящик, место, категория или пользователь
не найдены, `409` — дубликат имени места хранения, категории или логина,
`503` — сбой хранилища (файл повреждён), `422` — тело запроса не прошло
pydantic-валидацию. Тексты ошибок — пользовательский контракт, показываются
в интерфейсе как есть.

## Интерфейс

React-приложение (React 19 + Vite + TypeScript, единственная
библиотечная зависимость — `react-router-dom`) с русскоязычным UI в эстетике
calm dashboard: нейтральный цинк, приглушённый индиго-акцент, карточки с
радиусом 16 и мягкими тенями, caps-оверлайны, tabular-nums, focus-ring на
`<kbd>:focus-visible</kbd>`, поддержка `prefers-reduced-motion`.

**Страницы (маршруты):**

| Маршрут | Доступ | Страница |
|---------|--------|----------|
| `/login` | публично | Вход и регистрация (карточка по центру, переключатель «Вход ⇄ Регистрация») |
| `/` | вход | Обзор: плитки-счётчики (bento: «единиц на складе» + 3 компактных), «недавно обновлённое» (top 5 по `updated_at`) |
| `/boxes` | вход | Сетка карточек ящиков («ед. · поз.», место) + модалка создания (админ) |
| `/box?box={id}` | вход | Деталь ящика: инфо, QR-код (клик — увеличенный оверлей), редактирование (админ), содержимое, удаление (админ) |
| `/items` | вход | Вещи: фильтры чипами (ящик, категория), вид «Карточки ⇄ Таблица» (таблица — всем) |
| `/items` (таблица) | вход | Для админа — bulk-редактор: чекбоксы, инлайн-правка, «добавить строку», подсветка изменённых строк, сохранение (`PUT /api/items`) и массовое удаление; для роли «просмотр» — та же таблица, но только для чтения (без чекбоксов, правки и кнопок сохранения/удаления) |
| `/item/{id}` | вход | Карточка вещи: степпер количества, перенос select'ом, редактирование (PATCH только изменённых полей), удаление (всё — админ) |
| `/add` | админ | Добавление вещи: ящик, количество ≥ 1, категория (справочник + «➕ Новая категория…») |

| `/settings` | админ | Настройки (кнопка ⚙ в шапке): справочник категорий — добавление, переименование (обновляет вещи), удаление |
| `/users` | админ | Пользователи: таблица учётных записей, создание, редактирование (логин, пароль, роль), блокировка, удаление |

### Роли и доступ

- **«администратор»** — полный доступ: все мутации склада, справочник
  категорий, резервная копия и управление пользователями (создание,
  редактирование, назначение и смена ролей, блокировка, удаление).
- **«просмотр»** — только чтение данных склада; кнопки изменений скрыты,
  а серверные проверки (`401`/`403`) работают независимо от интерфейса.
- Самостоятельная регистрация создаёт роль «просмотр». **Самая первая
  учётная запись на пустом складе автоматически получает роль
  «администратора»** — иначе администратора некем создать; администратор
  затем создаёт и назначает роли остальным.
- Сессия: HttpOnly-cookie `storage_session` (SameSite=Lax), живёт до выхода
  пользователя («🚪 Выйти» в меню пользователя в шапке) или удаления
  учётной записи; блокировка учётной записи закрывает и её существующие
  сессии.

**Поведение:** светлая тема по умолчанию + тёмная с явным тогглом (выбор
хранится в `localStorage`, применяется до первой отрисовки); кнопка ⚙ в
правом верхнем углу ведёт на страницу настроек со справочником категорий:
добавление, переименование (обновляет категорию у всех вещей) и удаление
(вещи становятся «без категории», подтверждение показывает число затронутых
вещей); тосты на все мутации; полоса «Только что удалено… [Отменить]»
(~30 с, восстанавливает последнее удаление); confirm-диалоги на все
удаления; empty states с CTA и скелетоны при загрузке; на экранах ≤ 640px —
одна колонка и sidebar превращается в гамбургер slide-over. Данные после
мутаций перечитываются автоматически (backend сбрасывает свой кэш после
каждой записи).

**О дополнениях к API:** QR-код вставляется тегом `<img>` напрямую
(PNG-эндпоинт), CORS на него не действует. Поисковый запрос приводится к
нижнему регистру на клиенте (сервер сравнивает запрос с приведённым к
нижнему регистру «стогом сена»).

### Об аналогах

Композиция и приёмы (sidebar + глобальный поиск, плитки-статистика, чипы
категорий, QR на странице сущности, таблица с чекбоксами и bulk-панелью,
тосты/скелетоны/empty states) навеяны знакомыми продуктами ниши — Homebox,
Sortly, InvenTree, Snipe-IT, Grocy. Анализ выполнен **по базе знаний**:
на живые скриншоты/сайты референсов среда разработки не выходила, дизайн не
копирует референсы дословно (своя палитра из наследия проекта, русская
локализация, домен без фото).

## Порты и CORS

| Сервис | Адрес | Зачем |
|--------|-------|-------|
| Backend API | `http://localhost:8000` | REST API (таблица выше) и доки (`/docs`) |
| Frontend dev-сервер | `http://localhost:5173` | Страница React, порт фиксирован (strictPort) |

Запросы с фронтенда к API — кросс-доменные (5173 → 8000), поэтому backend
открывает их через `CORSMiddleware`. Список разрешённых источников — в
переменной `CORS_ORIGINS`; по умолчанию разрешён только
`http://localhost:5173`.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|------------|-------------|--------------|----------|
| `DATA_FILE` | нет | `/data/inventory.xlsx` | Путь к файлу-хранилищу (backend) |
| `APP_TITLE` | нет | `📦 Домашний склад` | Заголовок приложения |
| `BASE_URL` | нет | — | Базовый URL для QR-кодов ящиков; без него — адрес запроса |
| `CORS_ORIGINS` | нет | `http://localhost:5173` | Разрешённые источники фронтенда, через запятую |
| `VITE_API_URL` | нет | `http://localhost:8000` | Адрес API для фронтенда (frontend/.env) |

Шаблоны: `backend/.env.example`, `frontend/.env.example`.

## Важно: как правильно редактировать файл

Приложение читает файл в память и **перезаписывает его целиком** при каждом
изменении. Поэтому:

- ⚠️ **Не редактируйте файл в Excel одновременно с работающим приложением.**
  Если открыть файл в Excel, что-то поменять и сохранить, а затем внести
  изменение через приложение — правки из Excel будут **потеряны**.
- ✅ Если нужно поправить файл руками — остановите backend, отредактируйте
  файл и запустите снова.

Файл открывается в Excel, LibreOffice и Google Таблицах — можно посмотреть
глазами, распечатать или отдать кому-то. Резервная копия — `POST /api/backup`
(копия с отметкой времени рядом с файлом).

## Разработка и тесты

Проект покрыт тестами (pytest) на уровне домена, миграции legacy-формата,
хранилища, сервисного слоя и API. Фикстуры файлов данных создаются
программно через openpyxl; реальные данные в репозиторий не попадают.

```bash
# тесты backend — запускать из каталога backend/
cd backend
.venv\Scripts\python -m pytest

# с отчётом покрытия
.venv\Scripts\python -m pytest --cov=app --cov-report=term-missing

# проверка типов и сборка фронтенда
cd frontend
npm run build
```

Структура тестов:

```
backend/tests/
├── conftest.py                # генераторы xlsx-фикстур (новый и legacy-формат) + залогиненный админ
├── test_domain.py             # инварианты моделей, генерация ID
├── test_forms.py              # нормализация и выбор категории (домен)
├── test_helpers.py            # чистые хелперы данных
├── test_migration.py          # миграция legacy-файлов (слияние мест и т.д.)
├── test_excel_repository.py   # round-trip, атомарность, ошибки, сбои I/O
├── test_service.py            # сценарии: перенос, удаление, поиск, кэш
├── test_trash.py              # корзина: expiry, восстановление, detach/reattach
├── test_config_context.py     # конфигурация и сборка сервиса
├── test_api.py                # REST API: health, stats, ошибка хранилища → 503
├── test_api_auth.py           # авторизация: регистрация, вход/выход, 401/403, роли, пользователи
├── test_api_locations.py      # API мест: список со счётчиками, PATCH, 409 дубликат, корзина
├── test_api_boxes.py          # API ящиков: счётчики, деталь, PATCH, 404, detach вещей
├── test_api_items.py           # API вещей: CRUD, PATCH, bulk, поиск, категории
├── test_api_categories.py      # API категорий: справочник, add/rename/delete, вещи
├── test_api_trash.py           # API корзины: restore, purge, бэкап, кэш
└── test_api_qr.py             # QR-коды ящиков: PNG, 404
```

При доработках держите направление зависимостей:
`api → services → domain ← storage`. Домен не импортирует ничего из остальных
слоёв; openpyxl импортируется только в `app/storage/`; `fastapi` — только в
`app/api/`. Сервисы зависят от абстракции `InventoryRepository`
(typing.Protocol) — подменить хранилище можно в одном месте, `app/context.py`.

## Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| Страница 5173 показывает error-state | Backend не запущен. Проверьте `http://localhost:8000/api/health` или запустите `npm run dev:api`. |
| Запрос к API падает с CORS-ошибкой в консоли | Адрес фронтенда не в `CORS_ORIGINS` backend. Добавьте источник (по умолчанию нужен `http://localhost:5173`). |
| Постоянно перенаправляет на форму входа | Сессия не действует (выход, блокировка или лист «Сессии» удалён). Войдите снова; при утере пароля администратора остановите backend и удалите листы «Пользователи» и «Сессии» — при следующей регистрации первая учётная запись снова станет администратором. |
| `Файл повреждён или не является книгой Excel` | Файл испорчен. Восстановите из копии или удалите — приложение создаст новый. |
| Изменения не видны сразу | Данные кэшируются на 30 секунд; перезапуск backend сбрасывает кэш. |
| Порт 5173 занят | strictPort не даёт Vite переехать. Освободите порт или поменяйте его в `frontend/vite.config.ts` (и в `CORS_ORIGINS`). |

## Почему не Google Таблицы

Изначально проект использовал Google Sheets. От этого отказались:

- не нужен сервисный аккаунт, JSON-ключ и расшаривание таблицы;
- не нужны включённые Google Sheets/Drive API и квоты;
- нет зависимости от доступности внешнего сервиса;
- нет ограничения в 10 млн ячеек и лимитов на запросы;
- файл лежит у вас и открывается в Excel.

У Яндекс Таблиц, к слову, публичного API для работы с ячейками нет вообще —
только файловый API Яндекс Диска, что для учёта неудобно и рискованно.
